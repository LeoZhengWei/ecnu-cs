## 二、复现结果（真实数据，已写进报告与 PPT）

garden 场景，**无序输入、不给 COLMAP 位姿先验**，2 倍降采样（648×420），RTX 4090：

| 指标 | 数值 |
|---|---|
| PSNR / SSIM / LPIPS | **25.95 dB / 0.786 / 0.206** |
| 位姿误差（对比 COLMAP 真值） | **R° 0.155 / t 1.888** |
| 关键帧数 / 高斯数 | 156 / 362 044 |
| 流式重建墙钟耗时 | **62.7 s（185 帧，2.95 帧/秒）** |
| 峰值显存 | 19.5 GB |
| 渲染速度 | 约 480 帧/秒 |

论文在 A100、完整分辨率、有序输入下报 26.29 dB；本机为半分辨率、每 8 帧留 1 帧作测试集，差距来自分辨率与测试协议，量级一致。

## 三、现场演示建议（13 分钟 / 16 页）

1. **PPT 讲 10–12 分钟**：P2–P3 背景与定位压到 2 分钟，**主力放在 P4–P11 八页方法**（P9 局部 BA、P10 回环各压 75–85 秒，是全场核心），P12 是唯一的数据页；**P13 放作者自写的 CUDA BA 核——被问「工程贡献在哪」就翻这页**；P14 结论 + 边界清单收口；我们自己的复现数据（25.95 dB / 62.7 s）只在 P3 底部留一行口径，被问到再口头展开。
2. **现场跑一遍（2–3 分钟）**：
   ```bash
   ssh hjadmin@172.88.88.14
   cd /home/hjadmin/zhengwei/i3dgs-demo
   bash scripts/run_all_14.sh --ds 4
   ```
   脚本会自动挑最空闲的 4090，4 倍降采样下重建 + 渲染在几分钟内完成。
3. **交互式漫游（30 秒）**：服务器起 `gaussianviewer.py server`，本地客户端连上去拖动视角——客户端不用显卡。
4. **兜底**：若现场网络或机器不可控，直接播 `DEMO` 包里的 `演示视频/garden_ds2_walkthrough.mp4`。

## 四、迁移说明（相对上一版的变化）

演示项目已整体迁到 **172.88.88.14**（4×RTX 4090 / CUDA 12.6）：代码在 `/home/hjadmin/zhengwei/i3dgs-demo`，环境与数据在 `/datafast/zhengwei-i3dgs`（根分区只剩 16 GB，故分开放）。

迁移并非简单拷贝，期间又踩到 3 个新坑（已补进报告 5.2 节与使用说明）：

1. 换架构后 `TORCH_CUDA_ARCH_LIST` 必须从 `12.0` 改回 `8.9`，否则编译产物在 4090 上不可用；
2. 只搬 `torch.hub` 的仓库代码不够，`checkpoints/`（xfeat.pt、vgg16）与 HuggingFace 的 MegaLoc 缓存（`models--gberton--MegaLoc`）也必须一并迁移，否则启动即联网、断网即失败；
3. `--no-build-isolation` 下需自备构建后端，否则 DA3 与 graphdecoviewer 报 `BackendUnavailable: hatchling.build`。

数据与权重通过内网 rsync 从旧机器搬迁（约 50 MB/s），没有重新下载。
