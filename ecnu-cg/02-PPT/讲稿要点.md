## P2 研究背景：两条路都卡在同一个前提上

- 行业问题：拿到「一组照片 → 一个可漫游 3D 场景」，过去只有两条路，分歧不在算法细节，而在**什么时候允许开始计算**。
- 路线一 离线 SfM + 3DGS（COLMAP / GLOMAP + 3DGS、H3DGS、Octree-GS）：质量最高、全局一致，但必须等图全部到齐 → 现场零反馈。**前提：先有完整照片集合。**
- 路线二 增量 / 类 SLAM（Photo-SLAM、MonoGS、Droid-Splat、LongSplat）：边收边建，但新帧只与时间相邻的约 5 帧匹配 → 回访、拼接即断。**前提：输入是连续视频。**
- 两条路的前提是同一个东西：**帧序**——一条等它全部确定，一条假设它天然有序。
- 真实拍摄的四种病：① 等（返工成本最高）② 乱（1000 张约 50 万对）③ 漂（绕回差半米，重跑全局 BA）④ 爆（CityWalk 到第 795 / 4050 帧 OOM）。
- 收敛为三条必须**同时**成立的约束：即时（每帧数百毫秒）· 无序（不依赖帧序）· 全局一致（回环能修）。

## P3 摘要与贡献：它把哪件事第一次做成了

- 问题：3DGS 质量高、可实时渲染，但训练前必须由 SfM 离线解位姿；SfM 要等图到齐，且对乱序敏感。
- 做法：首个面向无序输入、具备全局一致性的即时 3DGS 重建——两级快速匹配 + GPU 局部 BA + 簇级回环图传播 + 渐进式层级。
- 结果：MipNeRF360 **1 分 17 秒 / 26.29 dB**（离线参考 8 分 50 秒 / 27.52 dB）；输入打乱只掉 **0.5 dB**。
- 四个贡献（各标"治哪个病、对应第几步"）：
  1. 无序序列快速匹配（治"乱"，步骤 ①–④）
  2. GPU 局部重建（治"慢"，步骤 ⑤、⑦）
  3. 簇级回环闭合（治"漂"，步骤 ⑥）
  4. 渐进式高斯层级（治"爆"，步骤 ⑦）
- 创新定位：不是从零发明。2025 直接前作已做到「免位姿 + 大场景 + 即时」，但要求图像有序、且不做回环；本文只补这两个假设。
- 底部一行实测口径：garden 2× 降采样 **25.95 dB / 62.7 s / 19.5 GB**，185 帧（差距来自分辨率与测试协议）。

## P4 方法总览：一帧进来，走完七步

- 设计哲学：**每帧做小事，偶尔做一次大事**（前者保实时，后者保不漂）。
- 七步：① 全局检索 ② 局部粗筛 ③ 精验建边 ④ 贪心选窗 ⑤ 局部 BA ⑥ 回环修正 ⑦ 高斯落位。
- 数据流：关键帧图像 → 加权协视图 G → 位姿 T_i / 三维点 X_j → 高斯集合 → 渐进层级。
- 节奏：①–⑤ 与 ⑦ 每关键帧都跑，⑥ 只在检测到回环时跑。
- 时间账（论文实测，单关键帧摊销）：视觉前端 27.8 ms · 局部 BA 40.5 ms · 回环摊销 121.6 ms · 渲染 480 fps。
- 容错：匹配失败的帧先"搁置"，后续出现相似帧再取出重试。

## P5 步骤① 全局检索：先不问"在哪"，只问"像不像"

- 做什么：新帧 → 全局描述子（论文 MixVPR，开源实现换 MegaLoc，4096 维）→ 与全部历史帧算余弦相似度 → 取 top-20。
- 关键取值：K = 20；`num_prev_keyframes_check = 20`。
- 公式：s(i, j) = d_iᵀd_j / (‖d_i‖‖d_j‖)，候选集 = top-20。
- 为什么：完全不吃帧序（乱序第一次被"原谅"）；n 帧只做 n 次检索而非 n² 次比对，约 1 ms / 1000 对，全链最便宜。

## P6 步骤② 局部粗筛：砍掉"看着像、其实没对上"的候选对

- 做什么：20 个候选各跑一次 XFeat 轻量匹配，按内点对数 |M_ij| 排序，留前 5。
- 关键取值：K′ = top-5；约 0.5 ms / 对。
- 公式：K′ = top-5{|M_ij|}。
- 为什么：这一级故意"便宜但粗糙"，任务是排序不是定论；被淘汰的是纯外观检索的典型假阳性（纹理像、几何一个点也对不上）。

## P7 步骤③ 精确验证：通过才建边

- 做什么：5 个候选跑 LightGlue 精配 + RANSAC 剔外点，内点 > 500 才建边，写进加权协视图。
- 关键取值：τ_m = 500（`min_matches_edge`）；约 4 ms / 对。
- 公式：|M_ij| > τ_m = 500 ⇒ (i,j) ∈ E，w_ij = 1/|M_ij|。
- 为什么：全链唯一产生共视约束的一步——后面所有位姿都由这些点对推出，边建错则后续全错。

## P8 步骤④ 选窗：从图里挑出最该一起优化的 20 帧

- 做什么：不是"最近 20 帧"，而是"与当前集合连接最强"的 20 帧；每次把累计 |M_ij| 最大的节点并入。
- 关键取值：N = 20 关键帧（`num_keyframes_localba`）、`num_prev_keyframes_miniba_incr = 5`。
- 公式（式 1）：S_{t+1} = S_t ∪ { argmax_{i∉S_t} Σ_{j∈S_t} |M_ij| }。
- 为什么：消融 NoKFSelection 26.29 → 24.56 dB；只比相邻 5 帧 24.78 dB。**选窗比匹配本身更影响质量。**

## P9 步骤⑤ 局部 BA：真正把位姿解出来的唯一一步

- 做什么：20 关键帧 + 约 1 万路标（按观测次数采样），每路标只被协视性选出的固定子集观测；LM 迭代，残差为 Huber 重投影误差。
- 关键取值：N = 20、K ≈ 1e4、LM 阻尼 mul_(1+λ) 自适应。
- 公式：min Σρ(‖u_ij − π(T_i,X_j)‖²) + λ‖δ‖²；Schur 补 **S = B − EC⁻¹Eᵀ** → Cholesky → 两次回代得 δ_T、δ_X。
- 为什么：C 是对角块可逐点求逆、B 稀疏，消元后只解相机；自写核函数使 20 帧/1 万点比 g2o、CUDA-BA 快约 5×。

## P10 步骤⑥ 回环修正：判定"两簇其实重叠"，再把修正摊回全图

- 判定：加权图距 d_G(C₁,C₂) > 10（`min_loop_size`）且跨簇有效匹配对 > 2；**不是跳数、不是时间差**。
- 求解：两簇各扩 N/2 帧做焊接 BA 得相对变换，由路标深度变化估尺度 → 组合成 Sim(3)。
- 传播：Dijkstra 求主干，按到锚点的测地距离比例插值：ΔT_α = exp(α·log ΔT)（旋转 6D 插值、尺度取对数）；每个高斯套同一变换。
- 为什么：**不跑第二次全局 BA**，回环代价从"再优化全场景"降到近似线性，摊销 121.6 ms/帧。

## P11 步骤⑦ 高斯落位：先把深度对齐，再按屏幕尺寸压成层级

- 深度对齐：图像切 4×4 块，逐块拟合 d_mono ≈ s_k·d_tri + o_k 再插值上采样（`depth_grid_size = 4`）；消融 NoLoDepAlgn 26.29 → 25.41 dB。
- 层级：screen < 0.5 px（`hierarchy_screen_size_threshold`）且可并数 > max(10%, 20 万)（`hierarchy_merge_ratio` = 0.1、`hierarchy_merge_min_count` = 2e5）→ kNN 取 4 邻居按 opacity × screen_size² 加权平均成父节点；叶节点卸载 CPU，渲染时贡献 > 1 px 异步回取（双缓冲）。
- 效果：不开层级 CityWalk 到第 795 帧 OOM；开了之后峰值 < 370 万高斯、显存 < 12.8 GB，层级达 8 层。
- 口径：论文正文写"按 KL 散度合并"，开源实现为 kNN 加权平均，量级接近，以代码为准。

## P12 论文实验：快一个数量级，只差 1–2 dB

| 数据集（有序） | 本方法 PSNR / 时间 | 离线参考 GLOMAP+3DGS(7k) | 结论 |
|---|---|---|---|
| TUM | 24.77 / 1:22 | 25.29 / 3:33 | 比 LongSplat 快约 75× |
| MipNeRF360 | 26.29 / 1:17 | 27.52 / 8:50 | 快 6.9×，差 1.23 dB |
| StaticHikes | 22.12 / 2:14 | 20.23 / 1:02:34 | 质量反超离线 |
| CityWalk（4050 帧） | 22.03 / 29:38 | Octree-GS 17.33 / 3:11:40 | 大场景最优 |

- 三个数字：**0.5 dB**（乱序只掉这么多，26.29 → 25.73）· **8.5**（平移 APE，Photo-SLAM 类 161+）· **324 ms**（平均每帧延迟）。
- 消融（横轴自 24 dB 起）：完整 26.29 · 不分块深度对齐 25.41（−0.88）· 去掉 VPR 只比相邻 5 帧 24.78（−1.51）· 只优化最后 20 帧 24.56（−1.73）。

## P13 不足与改进：哪些是硬伤，哪些能补

- 目前方法的不足（均来自论文自述）：① 低视差直接失效 ② 精度有天花板（NoGraphProp 证明图传播不比全局 PGO 差，但仍不如全局 BA）③ 上游依赖重（VPR + XFeat + LightGlue + DA3）④ 阈值靠经验（0.5 px / 10% / 图距 10 / 建边 500）。
- 以后的改进点（汇报人判断）：① 低视差帧降级只参与渲染 ② 在线粗 + 离线精（结束时 GLOMAP 回填一次全局 BA）③ 采集端闭环（覆盖率与重投影误差热图）④ 阈值自适应 ⑤ 验证还可扩展（打乱顺序、全分辨率、更多场景）。
- 收句：它把"精度"换成"时间"；补回精度只有两条路——离线回填，或让采集端少犯错。

## P14 结论：三句话带走

1. 它填的是一块空格，不是"更快的离线 SfM"——即时、无序、全局一致三者同时成立，此前没人做到。
2. 题眼是用"图上的距离"替换"全局优化的解"：判定看加权图距、求解用 Sim(3)、传播按测地距离。
3. 代价是真的：1.2 dB、更重的依赖链、低视差会失败——它换的是时间，不是免费午餐。
