## P2 摘要（独立页，课程要求）

- **问题**：3D Gaussian Splatting（3DGS）重建质量高、可实时渲染，但训练前必须由 SfM（COLMAP）离线求解相机位姿；SfM 要等**全部图像到齐**，且对**乱序采集**敏感。
- **现状缺口**：离线 SfM + 3DGS 质量好但慢且无即时反馈；SLAM 类增量重建能实时但**假设图像有序**。
- **本文做法**：首个面向**无序输入**、具备**全局一致性**的即时反馈 3DGS 重建。四个部件：两级快速匹配（视觉位置识别 + 协视图）、GPU 局部 BA 与精细高斯投放、基于簇的回环与图传播修正、渐进式高斯层级。
- **结果**：MipNeRF360 上 1 分 17 秒达到 26.29 dB（离线参考 8 分 50 秒 / 27.52 dB）；输入顺序打乱后仅降 0.5 dB；4050 帧大场景在 24 GB 卡上可跑。
- **我们的复现**：RTX 5090 + CUDA 12.8 环境从零搭建，跑通 garden 场景重建并导出漫游视频。

## P3 主要贡献点（独立页，课程要求）

1. **无序序列的快速匹配**：MixVPR 全局检索 → XFeat 粗筛 → LightGlue 精验，三级把匹配从 O(n²) 降到常数级；加权协视图 + 贪心选"高连通关键帧"。
2. **GPU 友好的局部重建**：自写 BA 核函数（稠密 Schur 补）比现有优化器快约 5×；**分块深度对齐**让高斯落点更贴表面。
3. **簇级回环闭合**：用协视图"跳数距离"判定回环，焊接窗口 BA + **Dijkstra 主干路径 + 测地插值**传播 Sim(3) 修正，**无需全局重优化**。
4. **渐进式高斯层级**：按屏幕尺寸合并/回取、叶节点卸载到 CPU，使大场景显存可控（峰值高斯 <370 万，显存 <12.8 GB）。

## P4 研究背景：位姿从哪里来

图示：两条路线对比

| 路线 | 代表 | 优点 | 缺陷 |
|---|---|---|---|
| 离线 SfM + 3DGS | COLMAP/GLOMAP + 3DGS | 质量高、全局一致 | 等全部图像；分钟~小时；无现场反馈 |
| 增量 / SLAM 类 | Photo-SLAM、MonoGS、DROID-Splat | 即时 | **假设有序**，乱序/回访即失效 |

一句话：**真实拍摄是无序的，但没有方法能同时做到"即时 + 无序 + 全局一致"**。

## P5 问题定义：什么叫"无序"

- 有序：视频抽帧，第 i 帧只与 i-1、i-2 匹配。
- 无序：手机相册式采集，来回走、回头补拍、两个片段交替。
- 三个挑战：① 无序中怎么快速找到重叠帧；② 局部优化规模不能随帧数爆炸；③ 回环后如何把修正同时作用到位姿**和**高斯。

## P6 方法总览：每帧做什么

流程条（每来一个关键帧）：
`两级匹配 → 更新协视图 → 回环检测 → 选 20 个高连通关键帧 → 局部 BA → (回环时) 焊接 BA + 主干传播 → 投放高斯 → 更新层级 → 30 次高斯优化 → 重试搁置帧`

设计哲学：**每帧做小事，偶尔做一次大事**。

## P7 核心一：三级匹配 + 加权协视图

| 层级 | 方法 | 作用 | 代价 |
|---|---|---|---|
| 1 | MixVPR 全局描述子 | top-20 候选 | ≈1 ms / 1000 对 |
| 2 | XFeat 局部特征 | 20 → 5 | ≈0.5 ms / 对 |
| 3 | LightGlue + RANSAC | 内点 >500 才接受 | ≈4 ms / 对 |

- 边权 = 内点数的倒数 → "最短路"= "最可信位姿链"
- 贪心选高连通关键帧：每步选与当前集合累计内点连接数最大者
- 消融：去掉 VPR，PSNR 26.29 → 24.78（**影响最大的一环**）

## P8 核心二：GPU 局部重建

- 关键帧 N=20（SLAM 通常只用 5 帧时间窗），路标点 K=10000
- 每个路标只被协视性选出的固定子集观测 → 避免观测数二次增长
- 自写 GPU kernel 计算残差与雅可比，稠密 Schur 补 → 比 g2o / CUDA-BA 快约 **5×**
- 高斯投放：**分块估计深度尺度/偏移**再插值上采样（消融：PSNR 26.29 → 25.41）

## P9 核心三：簇级回环 + 图传播

- 检测：两组"内部密、彼此疏"的关键帧簇，跳数距离 >5 且有效对 >2
- 求解：两簇各扩 N/2 帧做焊接窗口 BA → 锚点刚体变换 + 深度尺度 → Sim(3)
- 传播：Dijkstra 找累计权重最小的**主干路径**，按测地距离比例插值（旋转 6D、尺度对数插值）分配到全图；每个高斯记住"出生关键帧"，套用同一变换
- **代价与场景规模近似线性，不需要第二次全局 BA**

## P10 核心四：渐进式高斯层级

- 触发：屏幕尺寸 < 0.5 px 且占比 > 20%
- 合并：KNN 找 4 个最近高斯按 KL 散度合并，插入父节点；叶节点卸载到 CPU RAM
- 回取：贡献 > 1 px 时异步加载子节点（双缓冲防卡顿）
- 效果：CityWalk 不用层级到第 795/4050 帧就 OOM；用后峰值 370 万高斯、<12.8 GB、层级 8 层

## P12 我们的复现：环境与踩坑

- 硬件：RTX 5090 32G（sm_120）+ CUDA 12.8 + PyTorch 2.7.1
- 四个坑：① 5090 需 cu128（老 3DGS 生态是 cu11x）② `third_party/glm` 嵌套子模块为空 ③ `xfeat-lighterglue.pt` 从 GitHub 下载被重置 ④ HuggingFace 不可达
- 解决：`git submodule update --init --recursive`、本地权重优先、torch.hub 缓存预热、`HF_ENDPOINT=hf-mirror.com`
