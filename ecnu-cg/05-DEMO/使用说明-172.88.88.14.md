## 四、怎么跑

**方式 1：一键（推荐，现场演示用这个）**

```bash
cd /home/hjadmin/zhengwei/i3dgs-demo
bash scripts/run_all_14.sh                # 默认 garden + 2 倍降采样
bash scripts/run_all_14.sh --ds 4         # 更快
bash scripts/run_all_14.sh --scene counter
bash scripts/run_all_14.sh --viewer       # 只起交互式服务端
```

脚本会：环境自检 → 挑**最空闲**的那张 4090（4 张卡里选空闲最多的一张）→ 重建 → 渲染漫游视频 → 写 `results/SUMMARY_garden.txt`。空闲显存不足 10 GB 时自动把降采样从 2 改成 4。

**方式 2：分步执行**

```bash
export CUDA_HOME=/usr/local/cuda
export TORCH_CUDA_ARCH_LIST=8.9
export HF_ENDPOINT=https://hf-mirror.com
export HF_HUB_OFFLINE=1
PY=/datafast/zhengwei-i3dgs/envs/i3dgs/bin/python
BIG=/datafast/zhengwei-i3dgs

cd /home/hjadmin/zhengwei/i3dgs-demo/i3dgs          # ← 必须切到这个目录，见第五节第 5 条
CUDA_VISIBLE_DEVICES=2 $PY -u train.py \
  -s $BIG/data/MipNeRF360/garden \
  -m $BIG/results/garden_ds2 \
  --downsampling 2 \
  --da3_model_dir $BIG/weights/DA3-BASE

$PY scripts/render_path.py -m $BIG/results/garden_ds2 \
  --render_path $BIG/results/garden_ds2/sparse/0 \
  --out_dir $BIG/results/garden_ds2/video
```

**方式 3：带质量评估的重建**（报告里的数字就是这么来的）

```bash
CUDA_VISIBLE_DEVICES=2 $PY -u train.py -s $BIG/data/MipNeRF360/garden \
  -m $BIG/results/garden_ds2_eval --downsampling 2 \
  --da3_model_dir $BIG/weights/DA3-BASE \
  --test_hold 8 --test_frequency 20 --eval_poses
```

结果写入 `results/garden_ds2_eval/metadata.json`（PSNR/SSIM/LPIPS/R°/t）与 `test_images/`（24 张测试视角渲染）。

## 五、迁移过程中新踩到的 3 个坑（前 9 个见原使用说明）

1. **编译目标必须随架构改。** 换到 4090 后 `TORCH_CUDA_ARCH_LIST` 要从 `12.0` 改成 `8.9`；沿用 12.0 编出来的扩展在 4090 上无法执行。改对后单个扩展编译时间从十几分钟降到约 3 分钟。
2. **`torch.hub` 只搬了仓库代码、漏了权重缓存。** 迁移时若只同步 `~/.cache/torch/hub/verlab_accelerated_features_main` 这类仓库目录，程序仍会在启动时联网：
   - `torch.hub.load_state_dict_from_url` 要 `checkpoints/xfeat.pt`
   - lpips 要 `checkpoints/vgg16-397923af.pth`
   - MegaLoc 走 `hf_hub_download`，要 `~/.cache/huggingface/hub/models--gberton--MegaLoc/`（注意是 **gberton**，不是 gmberton）

   断网时前者报 SSL `UNEXPECTED_EOF_WHILE_READING`，后者报 `LocalEntryNotFoundError`。把这两个缓存目录一并搬过来才真正零联网启动。
3. **`--no-build-isolation` 下要自备构建后端。** 装 `depth-anything-3` 与 `graphdecoviewer` 会报 `BackendUnavailable: Cannot import 'hatchling.build'`，先 `pip install hatchling` 即可。

另外这台机器 **github.com 不可达**（SSL EOF），但 `codeload.github.com` 可用；**huggingface.co 不可达**，`hf-mirror.com` 可用。三个 git 依赖已用 codeload tarball 落到 `wheels/` 下，不必再联网。

## 六、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `FileNotFoundError: poses/ransac.cu` | 工作目录不对 | `cd i3dgs` 后再运行 |
| 启动就卡在 SSL `UNEXPECTED_EOF` | torch.hub 缓存缺权重 | 见第五节第 2 条 |
| `LocalEntryNotFoundError` | HF 缓存缺 MegaLoc | 见第五节第 2 条 |
| `BackendUnavailable: hatchling.build` | 缺构建后端 | `pip install hatchling` |
| `no kernel image is available` | 架构编错了 | 确认 `TORCH_CUDA_ARCH_LIST=8.9` 并删 `build/` 重编 |
| `CUDA out of memory` | 卡被别人占了 | `nvidia-smi` 看空闲，换卡或 `--ds 4`/`8` |
| `ImportError: moviepy.editor` | 装了 moviepy 2.x | `pip install moviepy==1.0.3` |
| 改代码后行为没变 | 删过 `models/cache` | 旧 TorchScript 缓存要清 |

## 七、迁移到别的机器还要注意

- **别只搬代码**：`data/`、`weights/DA3-BASE`、`~/.cache/torch/hub/{checkpoints,verlab_*,gmberton_*}`、`~/.cache/huggingface/hub/models--gberton--MegaLoc` 都是运行必需项。
- **架构与 CUDA 版本成对改**：sm_120↔cu128、sm_89↔cu126，改一个不改另一个必然出问题。
- **根分区小就挂大分区**：本机 `/` 只剩 16 GB，所以环境与数据全在 `/datafast`；脚本里的路径都指向那里。
