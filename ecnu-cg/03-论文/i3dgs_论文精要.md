## 一、一句话

**它把"和谁匹配"这件事从输入顺序里解放出来**：用视觉检索 + 协视图取代"前后帧相邻"这个假设，再用免优化的图传播取代全局 BA，于是乱序采集也能边拍边出结果。

---

## 二、问题定义：三个约束的交点

| 约束 | 现状 | 冲突点 |
|---|---|---|
| 要**即时反馈**（现场就知道拍没拍全） | 离线 SfM 精度高但必须等图到齐 | 无法现场判断 |
| 要是 **3DGS 的真实采集方式**（乱序：突然转身、回访补拍、多段拼接） | SLAM 类方法都默认"帧按顺序来" | 顺序假设一旦破了，匹配就失去方向 |
| 要**全局一致**（不能越走越偏） | 回环闭合要重跑全局 BA | 一跑几分钟，实时性归零 |

前两行是本文的动机，第三行是本文最难的地方。

> 一句话记住动机：**离线方法的问题不是慢，是"必须等"**；SLAM 的问题不是不准，是"默认有序"。

## 三、四个机制（主体，只讲这四个）

### 3.1 两级匹配 + 协视图选帧（解决"和谁比"）

级联，每一级替下一级筛候选，所以慢方法只在很小的集合上跑：

| 级 | 方法 | 输出 | 耗时 |
|---|---|---|---|
| ① 检索 | MixVPR，**4096 维**全局描述子，余弦相似度 | 取 top-**K = 20** | ≈ **1 ms / 1000 对** |
| ② 粗筛 | XFeat 穷举匹配，按内点数排序 | 保留 top-**K′ = 5** | ≈ **0.5 ms / 对** |
| ③ 精验 | LightGlue + RANSAC（基础矩阵） | 内点 > **τ_m = 500** 才收 | ≈ **4 ms / 对** |

匹配对通过后写进**加权协视图**：节点是关键帧，边权

```
w_ij = 1 / #inliers(i, j)        ← 内点越多，边越"短"，越优先走
```

选帧用**贪心扩张**：从新帧出发，每次把"与当前集合累计内点数最大"的节点拉进来（式 1），直到 **N = 20** 个。图中每节点约 10 条边，所以很快。

> **为什么这步是全文的地基**：有了它，新帧的邻居来自"整段历史里长得像的帧"，而不是"上一帧"。无序问题在这一步被消解。消融也印证：去掉它（NoVPR）掉到 **24.78 dB**，是掉得最狠的两项之一。

### 3.2 GPU 局部 BA（解决"20 帧也能算得快"）

| 参数 | 取值 | 说明 |
|---|---|---|
| 窗口 | **N = 20** 关键帧 | 比 DROID-SLAM 的 5 帧大得多，因为乱序更难 |
| 路标 | **K = 10000** 个 | 按观测次数做多项式采样 |
| 固定帧 | **n_f = 4** | 参与损失但不优化，随机抽 |

**真正的创新点不是"上 GPU"，而是压观测数**：旧方案里每个路标被窗口内所有帧观测，观测数随 N **二次增长**，N=20 就崩了。本文让每个路标**只被一个按协视性选出的固定子集观测**，把规模压回可控，同时保持稠密 Schur 补（实测比稀疏求解器更好）。

收益（表 15，20 位姿 / 1 万点 / 迭代 10 次）：g2o 461.4 ms → CudaBA 78.1 → On-The-Fly 79.7 → **Ours 15.9 ms（约 5×）**。

### 3.3 簇级回环 + 图传播（解决"偏了怎么回来"，全文最漂亮的一手）

**难点**：有序序列可以用时间戳判断"这块我最近没走过"，乱序下时间戳没意义。

**检测**：从匹配到的帧出发强制分成两个簇，若协视图里两簇相隔 **> τ_lc = 5 跳** 且小簇规模 **> τ_v**，判定回环（式 2）。**完全不用时间戳**，且天然过滤误匹配产生的小孤岛。

**焊接**：在两侧各取 N/2 帧构成焊接窗口 `W = S_{N/2}^{C1} ∪ S_{N/2}^{C2}`，跑局部 BA，**固定较旧的一侧**（它更可信、连着更多轨迹），另一侧叫自由簇。

**传播（免优化）**——这是最该记住的四步：

1. 算锚点在焊接前后的变换 `T_Δ = T_a^opt (T_a^init)^{-1}`，是 **SE(3)**；
2. 用**路标深度变化**估出尺度 `s_Δ`，复合得到 **Sim(3)** ← 单目尺度不可观测，所以不能只用 SE(3)；
3. 在协视图上用 **Dijkstra** 找一条累计边权最小的**主干路径** B，按到锚点的**测地距离比例** α 插值分配（旋转用 6D 表示、尺度用对数插值）；
4. 其余所有帧各自"就近挂"到主干节点，套用该节点的变换。

**高斯怎么办**：每个高斯在创建时**记下"出生关键帧"**，回环时套用与该关键帧完全相同的 Sim(3)，并同步更新尺度与旋转。所以不用重新训练高斯，也不用重新优化位姿。

> 作者自评（第 9 节）：图传播**不比全局 PGO 差**（NoGraphProp 消融），但**仍不如全局 BA（GLOMAP）**。这句是答辩"精度够不够"的标准答案。

### 3.4 渐进式层级（解决"显存"）

- 触发：屏幕尺寸 **< τ_l = 0.5 px** 的高斯，且这类高斯**占比 > 20%** 才合并（避免抖动）；
- 合并：4 近邻 + **KL 散度**（每 4 个并成 1 个父节点）；
- 回取：渲染时若某合并节点贡献 **> τ_h = 1 px**，换更细的子节点（双缓冲，避免卡顿）；
- 保底：**至少保留 50 个关键帧**，贡献低于最大值 **5%** 的帧卸载到 CPU。

效果：StaticHikes 峰值高斯 **-38%**（2.1M→1.3M）；CityWalk 不用层级在第 795 帧就 **OOM（>24 GB）**，用了层级 **3.7M / 12.8 GB** 跑完全程。

| 去掉什么 | PSNR | 掉幅 |
|---|---|---|
| NoVPR（改回只匹配最近 5 张） | 24.78 | **-1.51** ← 最狠 |
| NoKFSelection（改回优化最后 20 帧） | 24.56 | **-1.73** ← 最狠 |
| NoMatchVerif（只用 top-K 不验证） | 25.36 | -0.93 |

## 七、局限（作者自认 + 我们复现踩到的）

**作者自认三条**：
1. 纯旋转无法三角化（COLMAP 到 ORB-SLAM 都有）；
2. 图传播不比全局 PGO 差，但**不如全局 BA（GLOMAP）**，差距用质量换速度；
3. 质量仍低于 7000 次迭代的离线 3DGS（差 1–1.5 dB）。

**复现侧的三个事实**（答辩必须主动说，否则被追问很被动）：
1. 只跑通 **garden 一个场景**，**2 倍降采样**（648×420），**不是**全分辨率、不是全部数据集；
2. 用的是**有序**视频序列（按文件名排序），即"不给位姿先验"，但**没有验证真·无序**（跨段拼接、回访）；
3. PSNR 25.95 与论文 26.29 不能直接比——分辨率减半、每 8 帧抽 1 帧作测试集，协议不同。

## 八、代码与论文的三处差异（只有真复现过才知道）

| 项 | 论文写的 | 代码实际 |

## 九、8 个必答题（一句话版）

| 问题 | 答案 |
|---|---|
| 为什么用 Sim(3) 不用 SE(3)？ | 单目尺度不可观测，回环两侧尺度不一致；用路标深度变化估出 `s_Δ` |
| 为什么不重跑全局 BA？ | Schur 补最坏 O(n³)，一跑几分钟；图传播是毫秒级，精度接近 PGO、略逊 BA |
| 乱序下怎么判断回环？ | 协视图中两簇 **> 5 跳** 且小簇够大，代替时间戳 |
| 局部 BA 为什么敢用 20 帧？ | 乱序更难、小窗口不稳；靠"每路标只被协视子集观测"把规模压住 |
| 高斯怎么跟着位姿一起动？ | 记"出生关键帧"，套同一 Sim(3)，尺度与旋转同步更新 |
| 打乱输入会崩吗？ | 论文表 5 只掉 0.56 dB；**我们没做这个实验** |
| 和 SLAM 的本质区别？ | SLAM 默认前后帧相邻；本文把邻接关系交给检索+协视图，且回环修正免优化 |
| 精度到底差多少？ | 作者自认不如全局 BA；我们对标的是"快 7 倍、差 1.2 dB" |

## 十、五分钟能讲完的骨架

1. **痛点**：离线要等、SLAM 要有序，两头都堵在"3DGS 的真实采集方式"外面。
2. **关键一步**：把"和谁比"从顺序里拿出来 → VPR top-20 + 协视图选 20 帧。
3. **提速**：20 帧的 BA 靠"限制观测子集"才能在 GPU 上 15.9 ms 跑完。
4. **纠偏**：回环用跳数判定，修正靠一条主干路径摊给全图——不优化、不重跑。
5. **撑大**：层级把显存从 OOM 压到 12.8 GB。
6. **代价**：差 1.2 dB，换 6.9 倍速度。
